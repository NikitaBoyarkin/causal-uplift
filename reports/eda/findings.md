**Дата:** 2026-10-13
**Полный отчёт:** `reports/eda/eda-causal-uplift-2026-10-13.md`

## Датасет вкратце

`data/experiment.csv` содержит **20 000** строк, одна строка = **один пользователь** в
рандомизированном A/B-эксперименте (7 колонок: `user_id, segment, x_pre, treatment, y_cont,
y_bin, tau_true`). Временного периода нет — одноразовый срез. Качество данных в целом —
**отличное**: 0 пропусков, 0 дублей, диапазоны и категории валидны, рандомизация сбалансирована
(SRM p=0.161). Единственный содержательный риск — ground-truth колонка `tau_true` в датасете.

## Топ проблем качества

### Проблема 1: `tau_true` — ground truth в датасете (риск утечки)
- **Что:** `tau_true` — детерминированная функция `segment` (`corr = 1.000`), принимает 2 значения
  (0.60 `new` / 0.08 `returning`); колонка физически лежит в `data/experiment.csv`.
- **Влияние:** любой пайплайн, добавивший `tau_true` в признаки, получит идеальную, но полностью
  ложную модель (leakage). Сейчас не используется (`src/uplift.py:21`), но не защищено на уровне схемы.
- **Действие:** пометить колонку eval-only в схеме/данных; статическая проверка `tau_true ∉ FEATURES`.
- **Владелец:** дата-инженер / аналитик.

### Проблема 2: `corr(τ)` — между-сегментная метрика, а не ITE-ранкинг
- **Что:** `tau_true` принимает только 2 значения (`src/eval.py:92-108`), поэтому
  `corr_pearson_with_true` — point-biserial корреляция между сегментами, не внутри-сегментный
  ранкинг индивидуального эффекта.
- **Влияние:** `corr(τ)=0.66` можно прочитать как «модель ранжирует ITE», хотя она лишь ловит
  сегментный разрыв. README это футнотит (README.md:116-118).
- **Действие:** принять риск (документировано) либо защитить тестом; не подавать как ITE-ranking.
- **Владелец:** аналитик.

### Проблема 3: сырой разрыв по `segment` противоположен эффекту лечения (ловушка Симпсона)
- **Что:** сырой `y_cont` mean: `returning` 3.362 vs `new` 2.006 (×1.68) — но это разный baseline
  (у `new` `x_pre` mean 0.001 vs 1.492), а не эффект.
- **Влияние:** можно ошибочно заключить, что «у `new` исход хуже», хотя по эффекту лечения `new`
  отвечает в ~8× сильнее.
- **Действие:** всегда читать эффект (diff-in-means по рукавам внутри сегмента), а не сырой срез.
- **Владелец:** аналитик.

## Что в порядке

- Пропуски — 0 во всех 7 колонках.
- Полные дубликаты строк и дубликаты по ключу `user_id` — 0.
- Категории валидны: `treatment ∈ {0,1}`, `segment ∈ {new,returning}`, `y_bin ∈ {0,1}`.
- Диапазоны правдоподобны: `x_pre` [−4.26, 5.69], `y_cont` [−2.87, 8.22].
- Рандомизация чистая: SRM p=0.161, `segment`×`treatment` p=0.883, `x_pre` SMD=−0.006.
- `x_pre` коррелирует с `y_cont` (r=0.667) — пре-периодная ковариата пригодна для CUPED.
- README truth check: все проверяемые из данных числа **REPRODUCED**, MISMATCH нет.
