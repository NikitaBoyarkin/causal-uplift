# Пред-регистрация решения: кампания на сегменте `new`

## 1. Статус

Зафиксировано **до** анализа. Версия 1.0, дата 2026-10-25. Изменять правило
после просмотра данных запрещено; любая правка — новая версия с новой датой.
Правило продублировано константами в `src/config.py` (`DECISION`) и кодом
`src/decision.py`; тест `tests/test_decision.py` связывает документ и код.

## 2. Гипотеза и первичная метрика

Гипотеза: таргетированная кампания на сегменте `new` окупается.

Первичная метрика — **эмпирический разрыв конверсии** в сегменте `new`
(доля конверсий в treatment минус control) на полном фрейме n = 20 000.
Доверительный интервал — перцентильный бутстрап, уровень 95%. Это
маргинальный сегментный ATE, а не предсказание модели.

## 3. Решающее правило

Break-even по uplift: `break_even = campaign_cost_per_user / value_per_conversion`.
При цене конверсии 40 и стоимости 2 на пользователя: break_even = 0.05.

Три исхода (нижняя `lo` и верхняя `hi` границы 95% CI):

- `lo > break_even` → **ship**
- `hi < break_even` → **no_ship**
- иначе (CI накрывает break_even) → **inconclusive**

Константы: `value_per_conversion = 40`, `campaign_cost_per_user = 2`,
`ci_level = 0.95`, `target_segment = new`.

## 4. Цена ошибки

- **ship, эффекта нет** (`ship_if_no_effect`): платим за кампанию впустую —
  `campaign_cost_per_user * n_target`.
- **no_ship, эффект есть** (`no_ship_if_effect`): теряем прибыль —
  `max(observed * value - cost, 0) * n_target`.
- **worst_case_total** — максимум из двух веток.

«Промах» — это деньги: либо потраченный впустую бюджет, либо упущенная
прибыль. Правило выбирает исход, при котором цена ошибки ниже.

## 5. Вторичные метрики без права голоса

AUUC, QINI и uplift@20% на этом n **шум-доминированы**: даже идеальный ранкер
по известному `tau_true` даёт QINI лишь ~2σ над нулевым эталоном
(`reports/metrics.json`, блок `null`). Поэтому они **не участвуют** в решении
и не могут ни подтвердить, ни отменить вердикт. Единственная первичная
метрика — эмпирический разрыв из п. 2.

## 6. Правило остановки

Фиксированный объём n = 20 000, **один** анализ, без подглядываний и
промежуточных решений. Никаких повторных прогонов «пока не станет значимо».

## 7. Что изменило бы вердикт

Если 95% CI накрывает break-even (`lo <= break_even <= hi`), вердикт —
`inconclusive`: данных не хватает, чтобы отличить окупаемость от убытка.
Более широкий CI (меньше n) повышает шанс `inconclusive`, но не меняет правило.

## 8. Анти-утечка

`tau_true` — скрытая величина, используется **только для оценки** качества
моделей и никогда не входит в решение как признак. Вердикт считается по
наблюдаемым `y_bin` и флагу `treatment`, доступным в проде.

## 9. Чувствительность

Break-even = cost / value. При ±50% к стоимости break-even смещается
пропорционально (2 → 3 даёт 0.075; 2 → 1 даёт 0.025); при ±50% к цене
конверсии — обратно пропорционально (40 → 60 даёт ≈0.033; 40 → 20 даёт 0.10).
Вердикт меняется, если сдвинутый break-even пересекает границу CI. Точные
числа не фиксируются заранее — их даёт формула, а не подгонка под данные.
